# User flow и формат сценария

## Путь проводника

```
Вход в смену (профиль по логину)
      │
      ├─ Уведомления: «новый рейс», «рейс недели», «сгорают 120 очков»
      │
Каталог ── рейс недели (общий сценарий для всех) · рейсы смены ·
      │      отдельные ситуации в адаптивном порядке
      │
      ▼
РЕЙС ── инцидент за инцидентом (1 → 2 → 3), узел за узлом:
      реплика пассажира / событие в вагоне
      таймер (для критических узлов) ─── не успел → ветка timeout,
      варианты ответа с пометкой шага ролевой модели      ситуация идёт дальше
      │  после каждого хода: обе шкалы, причина изменения и «что было бы,
      │  если» — ветка, которую вы не выбрали
      │
      ├─ конец инцидента → экран перегона: исход, память рейса, шкалы
      │                     переходят дальше, рейс продолжается
      ▼
Финал рейса (good / neutral / bad по каждому инциденту)
      │
      ▼
РАЗБОР: балл и оценка · что это значит (содержательные советы) ·
        компетенции за рейс · ход за ходом с причинами и «как лучше» ·
        нормативная основа сценария
      │
      ├─→ Опыт → уровень (Стажёр → … → Наставник), серия дней
      ├─→ Достижения (проверяются по итогу рейса)
      ├─→ Рейтинг: личный, по бригаде, по депо; отдельная таблица челленджа
      └─→ Аналитика: динамика компетенций, «где ошибаются чаще всего»
```

## Формат сценария

Сценарий — один YAML-файл в `content/scenarios/`. Минимальный пример:

```yaml
id: demo
title: Пассажир громко говорит по телефону
summary: Стандарт-класс, соседи оборачиваются.
segment: Тверь — Санкт-Петербург
minutes_to_stop: 35
car_class: стандарт
difficulty: 1
sources: ["«Примеры ситуаций…», ситуация 12"]
start: call

nodes:
  call:
    speaker: narrator
    text: Пассажир в 14-м ряду громко говорит по телефону.
    timer: 20              # секунды; обязательна ветка timeout
    critical: false        # у критического узла быстрый ответ даёт хладнокровие
    timeout:
      goto: finish
      reason: Замечание так и не прозвучало — соседи ехали в раздражении
      effects: {loyalty: -5}
    options:
      - id: polite
        step: acknowledge        # acknowledge | rule | solution | assure | action
        text: «Будьте добры, чуть тише — благодарю за понимание»
        reason: Мягкая просьба, а не требование (методичка, ситуация 12)
        effects:
          loyalty: 6
          safety: 0
          competences: {deescalation: 2}
          set: [asked]           # флаг для условий в следующих узлах
        goto: finish
      - id: tambour
        step: solution
        text: Предложить продолжить разговор в тамбуре
        requires: [asked]        # вариант доступен только после первого шага
        reason: Индивидуальное обращение без внимания салона
        better: Сначала мягкая просьба, потом альтернатива
        effects: {loyalty: 4}
        goto: finish
  finish:
    ending: good                 # good | neutral | bad
    text: Салон спокоен, пассажир перешёл на тихий тон.
```

Загрузчик проверяет файл целиком: несуществующий `goto`, таймер без ветки
`timeout`, неизвестная компетенция, недостижимый узел, сценарий без финала —
ошибка при старте, а не в середине партии. Отдельно есть валидатор для
методиста: `python backend/validate.py` ловит ещё и варианты без причины,
варианты, которые ни на что не влияют, и память рейса, которую никто не
выставляет.

## Рейс: несколько инцидентов с памятью

```yaml
# content/trips/day-751.yaml
id: day-751
title: Дневной рейс 751
route: Москва — Санкт-Петербург, вагон комфорт-класса
segments: [double-seat, lost-child, medical]   # играются по порядку
memory_labels:                                  # что игрок увидит в «памяти рейса»
  goodwill_car: Салон на вашей стороне — спор решён по-человечески
  car_tense: Вагон помнит публичный спор
```

Внутри рейса шкалы и флаги не обнуляются. Память используется двумя способами:

```yaml
# вариант доступен, только если салон настроен к проводнику хорошо
- id: neighbour_help
  requires: [goodwill_car]
  text: Попросить пассажиров, с которыми вы уже нашли общий язык, помочь

# тот же ход ведёт в другой узел, если вагон помнит публичный спор
- id: screen
  goto: finish_ok
  goto_if:
    - flag: car_tense
      goto: filmed
```

## Как за минуту поменять правило

- **Добавить развилку** — дописать вариант в `options` нужного узла
  и, если надо, новый узел. Перезапуск не нужен только для контента в момент
  разработки: сценарии читаются при старте процесса.
- **Изменить цену решения** — поправить `effects` у варианта.
- **Изменить правило ролевой модели** — `engine.SEQUENCE_RULES`: там
  три записи вида «шаг X после шага Y → столько-то лояльности и причина».
- **Изменить вес шкал в итоге** — `engine.score`, строка
  `state.safety * 0.6 + state.loyalty * 0.4`.
- **Добавить достижение** — запись в `content/achievements.yaml`; условия
  ограничены белым списком полей, опечатка в названии поля не пройдёт молча.

## Шесть готовых сценариев

| Сценарий | Перегон | Чему учит |
|---|---|---|
| Пассажиру стало плохо | Москва — Тверь, 7 минут до остановки | вызов медиков к платформе через начальника поезда; запрет на личные лекарства; работа с чужим стыдом |
| Два пассажира на одно место | Москва — Тверь, бизнес-класс | не занимать сторону до проверки билетов; сбой перевозчика компенсируется высшим классом; право на жалобу и границы съёмки |
| Пассажир с признаками опьянения | Тверь — Санкт-Петербург | мягкий отказ с альтернативой; не называть состояние вслух и по рации; ПТБ и начальник поезда; забота о соседях |
| Бесхозная вещь в салоне | Тверь — Бологое | вещь не трогать и не переносить; ПТБ и начальник поезда; как не поднять панику формулировкой |
| Ребёнок потерялся | Тверь — Бологое | приоритет между ребёнком и рацией; объявление без персональных данных; не уводить ребёнка с места |
| Вынужденная остановка в пути | Бологое — Санкт-Петербург | только достоверная информация; двери в пути; паническая атака; «окна не открываются» с объяснением |
