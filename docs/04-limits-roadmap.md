# Ограничения решения и план развития

## Что сознательно не сделано

| Ограничение | Почему |
|---|---|
| Аутентификации нет: вход по логину без пароля | демо-стенд; в контуре ВСМ вход идёт через корпоративный SSO, и профиль должен приходить из HR-системы, а не заводиться самим сотрудником |
| SQLite вместо СУБД | запуск жюри одной командой важнее нагрузочных характеристик; слой хранилища изолирован и меняется без правки игровой логики |
| Три сценария вместо каталога из 51 | методичка даёт 51 ситуацию, но ценность в глубине ветвления, а не в числе линейных ситуаций; формат сценария позволяет добавлять остальные без кода |
| Нет редактора сценариев в интерфейсе | YAML правится в репозитории; веб-редактор — следующий шаг, формат под него уже готов |
| Фронтенд без сборки, не PWA | за отведённое время надёжный запуск важнее офлайн-режима; мобильная вёрстка адаптивна, но установки на телефон нет |
| Образ Docker не проверялся запуском | на машине разработки Docker не установлен; основной путь — локальный запуск из README, он проверен |
| Разбор ссылается на источники сценария, а не на конкретный пункт | тексты СТО РЖД из датасета цитируются на уровне документа; пунктовая привязка требует сверки с актуальной редакцией |

## План развития

**Ближайшее (недели)**

1. Веб-редактор сценариев для методистов: тот же YAML, но с визуальным
   графом узлов и проверкой связности при сохранении.
2. Остальные ситуации из методички — приоритет по данным `hotspots`:
   сначала те темы, где проводники ошибаются чаще.
3. Рейс из нескольких инцидентов подряд с общей памятью пассажиров:
   тот, кому отказали на первом перегоне, иначе ведёт себя на третьем.
4. Уведомления наружу (push/почта) и недельные челленджи с общим сценарием.

**Средняя перспектива**

5. Интеграции: SSO и профиль из HR, назначение обучения из LMS, выгрузка
   результатов в учётную систему подготовки.
6. Роль инструктора: назначить сценарий бригаде, посмотреть разбор
   конкретного рейса, оставить комментарий к ходу.
7. Свободная реплика вместо выбора варианта: ответ проводника распознаётся
   в один из ходов, а исход по-прежнему считает детерминированное ядро —
   так модель не может «сломать» оценку, а офлайн-режим сохраняется.

**Дальше**

8. Голосовой режим для отработки интонации.
9. Мультиплеер «проводник — начальник поезда» на одном инциденте.
10. Калибровка эффектов по реальной статистике обращений пассажиров:
    сейчас веса расставлены экспертно по методичке.
