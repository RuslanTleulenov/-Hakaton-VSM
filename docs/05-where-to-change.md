# Где что менять за минуту

Шпаргалка на защиту: жюри просит изменить развилку или правило шкалы —
вот точные места. Всё проверяется валидатором `python backend/validate.py`.

| Что изменить | Файл | Что именно |
|---|---|---|
| Добавить вариант ответа | `content/scenarios/<id>.yaml` | запись в `options` нужного узла: `id`, `text`, `step`, `effects`, `reason`, `goto` |
| Изменить цену решения | там же | `effects: {loyalty: …, safety: …, competences: {…}}` |
| Добавить развилку | там же | новый узел в `nodes` + `goto` на него из варианта |
| Поставить таймер | там же | `timer: 20` и обязательная ветка `timeout` (иначе загрузка упадёт) |
| Сделать вариант условным | там же | `requires: [флаг]` / `forbidden: [флаг]`, флаг выставляется `effects.set` |
| Развести один ход по памяти | там же | `goto_if: [{flag: car_tense, goto: filmed}]` |
| Правило ролевой модели | `backend/app/engine.py` | список `SEQUENCE_RULES` — «шаг X после шага Y → столько лояльности и причина» |
| Вес шкал в итоговом балле | `backend/app/engine.py`, `score()` | `state.safety * 0.6 + state.loyalty * 0.4` |
| Штраф за пропущенный таймер | там же | `- 3 * timeouts` и `composure: -2` в `_timeout` |
| Порог «быстрого» решения | `backend/app/engine.py` | `FAST_DECISION_SHARE = 0.5` |
| Когда показывать альтернативу | `backend/app/engine.py` | `ALTERNATIVE_GAP = 6` |
| Добавить достижение | `content/achievements.yaml` | запись с `condition` из белого списка полей |
| Уровни проводника | `backend/app/service.py` | `LEVELS` |
| Состав рейса | `content/trips/<id>.yaml` | `segments` — список сценариев по порядку |
| Расшифровка памяти рейса | там же | `memory_labels: {флаг: «что это значит»}` |
| Срок сгорания баллов | `backend/app/service.py` | `POINTS_EXPIRE_DAYS`, `CHALLENGE_BONUS_XP` |

## Три вопроса, которые точно зададут

**«Покажите, где считается балл»** — `backend/app/engine.py`, функция `score()`:
итог `0.6 × безопасность + 0.4 × лояльность`, плюс средний бонус за исходы
инцидентов рейса, минус 3 за каждый пропущенный таймер. Безопасность весит
больше, потому что сервис на ВСМ не оплачивается риском.

**«Почему порядок реплик важен»** — `SEQUENCE_RULES` в том же файле. Методичка
задаёт ролевую модель: признать → правило → решение → заверить. Проводник может
сказать всё верное, но начать с правила — и пассажир услышит отписку. Движок
сравнивает шаг текущего варианта с шагом предыдущего хода и начисляет
отдельно от самих эффектов реплики. Тест: `test_role_model_order_changes_loyalty`.

**«А таймер нельзя обмануть из консоли?»** — нет: браузер вообще не передаёт
время. В таблице `runs` лежит `node_shown_at`, и при ходе сервер сам считает
разницу (`service.choose`). Клиент может прислать только «я не успел»
(`option_id: null`), а решение, истёк ли таймер, принимает ядро.

## Как добавить сценарий целиком

1. Скопировать любой файл из `content/scenarios/` как образец.
2. Взять ситуацию из методички «Примеры ситуаций взаимодействия поездного
   персонала с пассажирами» и выписать в `sources` её номер.
3. Собрать 6–10 узлов: минимум два финала, у критических — таймеры.
4. `python backend/validate.py` — он поймает битые ссылки, узлы без причин,
   варианты, которые ни на что не влияют, и недостижимые узлы.
5. Перезапустить бэкенд: контент читается при старте процесса.
