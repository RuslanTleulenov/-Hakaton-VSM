# Перегон — геймифицированный тренажёр проводника ВСМ

Кейс «Геймификация для ВСМ», хакатон Московского транспорта.

Тренировка — это **рейс**: несколько нештатных ситуаций подряд на маршруте
Москва — Санкт-Петербург. Проводник принимает решения на таймере, видит, как
каждое из них двигает **лояльность пассажира** и **рейтинг безопасности**,
а после рейса получает разбор: почему изменилась каждая шкала, как можно было
лучше и что было бы, выбери он другую ветку. Очки идут в профиль компетенций,
достижения, серии и рейтинг бригад.

Сценарии построены не на выдумке, а на данных кейса: методичка
«Примеры ситуаций взаимодействия поездного персонала с пассажирами»
(51 ситуация) и стандарты СТО РЖД по обслуживанию пассажиров ВСМ.

## Что именно сделано

| Требование кейса | Где реализовано |

| Челленджи и серии | «Рейс недели» с отдельной таблицей, серии дней, сгорающие баллы челленджа |

## Четыре собственных решения, которых нет в «квизе с таймером»

1. **Ролевая модель как механика, а не как справка.** Методичка задаёт
   порядок: признать ситуацию → обозначить правило → предложить решение →
   заверить. Каждый вариант помечен шагом этой модели, и движок считает
   **порядок** отдельно от самих реплик: правило, сказанное до признания,
   стоит −4 лояльности; решение после признания — +3. Правила лежат
   в `engine.SEQUENCE_RULES`.
2. **Память пассажиров между инцидентами.** Рейс — это не набор ситуаций:
   флаги и обе шкалы переезжают из инцидента в инцидент. Салон, с которым
   проводник по-человечески решил спор о месте, помогает ему в медицинском
   инциденте — появляется вариант «попросить соседей помочь». Вагон, видевший
   публичный спор, ведёт тот же ход в другую ветку: сосед достаёт телефон.
3. **Таймер от маршрута, а не от игры.** Часть действий возможна только до
   остановки: медиков вызывают к платформе, пассажира передают полиции на
   вокзале. Поэтому у сценария есть `minutes_to_stop`, а время решения считает
   **сервер**: в БД лежит момент показа узла, и клиент не может «остановить»
   таймер из консоли.
4. **Шкалы тянут в разные стороны осознанно.** Итог — `0.6 × безопасность +
   0.4 × лояльность`: сервис не оплачивается риском, и это видно в баллах.
   При этом почти в каждом узле есть вариант, сохраняющий обе шкалы, —
   он отличается формулировкой, а не смыслом.

## Запуск

Нужен Python 3.11+ и ничего больше: база — SQLite, фронтенд без сборки.

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt   # Linux/macOS: .venv/bin/python
.venv/Scripts/python backend/seed.py                      # демо-данные: 5 проводников, рейтинг, токен интеграции
.venv/Scripts/python -m uvicorn app.main:app --app-dir backend --port 8040
```

- Интерфейс — <http://localhost:8040>
- OpenAPI/Swagger — <http://localhost:8040/docs>

Тесты (33: ядро, рейсы, геймификация, API) и проверка контента:

```bash
.venv/Scripts/python -m pytest backend/tests -q
.venv/Scripts/python backend/validate.py
```

Контейнеризация: [`Dockerfile`](Dockerfile) и [`docker-compose.yml`](docker-compose.yml)
(`docker compose up --build`). На машине разработки Docker не установлен,
поэтому образ не проверялся запуском — локальный путь выше проверен
и является основным.

## Структура

```
backend/app/domain.py    типы сценария и рейса: узлы, варианты, эффекты, память
backend/app/engine.py    ядро: ветвление, таймеры, шкалы, ролевая модель, итог
backend/app/loader.py    загрузка YAML + валидация ссылок и достижимости узлов
backend/app/db.py        схема SQLite и миграции колонок
backend/app/service.py   партии, профиль, достижения, рейтинг, челлендж, аналитика
backend/app/main.py      HTTP API (FastAPI), интеграции, раздача фронтенда
backend/seed.py          демо-данные: партии проигрываются тем же ядром
backend/validate.py      проверка контента для методиста, код возврата 1 при ошибках
content/scenarios/*.yaml шесть сценариев на данных кейса
content/trips/*.yaml     два рейса из трёх инцидентов с расшифровкой памяти
content/achievements.yaml  двенадцать достижений
frontend/                интерфейс без сборки (HTML + CSS + JS, Moscow Sans)
docs/                    архитектура, API, user flow, ограничения, безопасность, демо
```

## Данные и безопасность

- Все профили, бригады и депо — **синтетические**, персональных данных
  пассажиров и сотрудников в стенде нет (152-ФЗ). Подробно — [`docs/06-security.md`](docs/06-security.md).
- Секретов и ключей в репозитории нет: токен интеграции лежит в БД и
  печатается `seed.py` при наполнении.
- Ошибки предсказуемы: 404 / 409 / 422 / 401, а битая ссылка между узлами
  сценария — ошибка при загрузке, а не в середине партии.
